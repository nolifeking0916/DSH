# DSH 上下文注入：收敛为单一来源

## 1. 结论

DSH 每轮对话的上下文供给，收敛为**一条注入通道**：`@local/context-inject` 独占供给「经验 + 技能 + 记忆」三类内容，每轮只发一条消息、每类内容各设配额；其余两个历史插件（`memos-autoinject`、`wikiskill-inject`）**停用但不卸载**，源码留在仓库、一行配置可回滚。

理由：这三类内容里，只有「经验」与「历史记忆」是内核不提供的，插件层不可替代；「技能」内核本来就有全量目录，插件只需提供相关性排序，不必重复供给全量。

## 2. 现状诊断（2026-10-24 实测）

| 指标 | 三插件并跑 | 单源（收敛后） |
|---|---|---|
| 每轮注入字符 | 1,519–1,988 | **782–788** |
| MemOS 请求 | 4 次/轮（串行） | **2 次/轮**（记忆视图 + 技能视图并行） |
| 额外延迟 | +1,309–1,430 ms | +676～1,124 ms |
| 条目级重复 | 26.2%（21/80） | **0** |
| 注入连续性 | 只有会话第一轮 | **每轮都有** |
| 采纳率（16 题 A/B） | 16.7%（人工复核 13.3%） | 同左（用的是单源 render 输出） |

分路采纳率：**经验 25.0% ＞ 技能 22.7% ＞ 记忆 9.1%**。

并跑的根因是 profile 层同名条目覆盖了插件自带补丁：`~/.dsh/profiles/desktop/cordis.patch.yml` 里的 `- id: wikiskill-inject / disabled: false` 压过了 `plugins/context-inject/cordis.patch.yml` 里的 `disabled: true`（patch 层级：bundle → profile → `$DSH_HOME` → `--patch`，同 id 后写覆盖）。

更根本的缺陷：`agent/pre-step` 的 `step` 是**会话内累计**的（实测涨到 113），而三个插件都写死 `injectStep: 1` —— 注入条件实际变成「会话的第一次 agent step」，第一轮之后**静默失效**（插件显示 active，日志一行都没有）。

原生侧最大的一块是内核技能目录 `<available_skills>`：**76 条 / 20,099–20,206 字符**（每条描述上限默认 500，实测 11 条被截断），是插件三块合计（1,966）的 10 倍。

## 3. 目标架构

**单一注入源** = 每轮只发一条注入消息，且每类内容只有一个供给路径。

| 内容 | 供给路径 | 形态 |
|---|---|---|
| 经验 | 本地 `~/.dsh/wiki/patterns/`（零请求，2-gram 匹配） | `- 标题：结论 → /原文件路径`（带路径，模型可回读原文） |
| 技能 | MemOS skill 视图（KB 检索）；命中为 0 或请求失败 → 本地 `~/.dsh/skills` 关键词兜底 | 日志标注来源 `(memos)` / `(local)` |
| 记忆 | MemOS 记忆视图（事实 + 偏好） | 常驻 ≤ 2 条、本地相关性下限 0.55；其余由模型按需调 `search_memory` |

规则：

1. **每轮判据 = 用户消息是否变化**，不用 `step`（step 会话内累计）。
2. **每轮一条消息**：插件块每轮新增会累积，单源必须自己判重。
3. **按类配额**：经验 340 / 技能 220 / 记忆 240，总预算 800 等比缩放；单类超配额就截断该条并停。
4. **fail-open**：MemOS 不可达时仍注入经验 + 本地技能；全空则不注入。
5. **不重复供给内核已有的内容**：技能清单只给相关性排序，不再复制内核的全量目录。
6. **原生块只对齐、不改内核机制**：内核块不可关停，只做裁剪/去重。

## 4. 迁移步骤

1. 先补齐 context-inject 的两处缺口（经验带路径、技能本地兜底）——否则停用旧插件会当场丢能力。
2. 改预算为按类配额，并修好【记忆】段被挤成 0 条的问题（room 实测 −53）。
3. 把「每轮注入」判据从 `step===1` 改为「用户消息是否变化」。
4. 删掉 `~/.dsh/profiles/desktop/cordis.patch.yml` 里两个旧插件的 `disabled: false` 覆盖行 → 热生效，无需重启。
5. 观察一轮：无回归则保持停用；最终卸载作为收尾动作（卸载会移除 bundle 行并让插件自带补丁报 `entry not found`，所以放在最后、可回滚）。

**回滚**：把第 4 步那两行写回即可（profile patch 改动由 dsh-hmr 热生效，秒级）。插件源码全程留在仓库 `plugins/`。

## 5. 验收口径

| 指标 | 阈值 | 现测 |
|---|---|---|
| 采纳率 | ≥ 15%（人工复核口径 ≥ 13%） | 16.7% |
| 每轮注入字符 | ≤ 900 | 788 |
| MemOS 请求 | ≤ 2 次/轮 | 2 |
| 条目级重复 | ≤ 5% | 0 |
| 注入连续性 | 任意连续 3 轮真实会话都有 `inject:` 记录 | 达成 |
| 经验/技能/记忆分路 | 经验 ≥ 20%；记忆 ≤ 15% 时优先降配额 | 25.0% / 22.7% / 9.1% |

采纳只证明相关性，不等于答案正确率提升；正确率不在本方案验收范围。

## 6. 已知缺口与后续

- **原生技能目录裁剪**：`catalogDescriptionMaxLength` 默认 500，已在 profile patch 写入 160，但本次热重算未能让运行中的插件实例重新 apply（配置在树里、插件仍用 500；新会话实测仍是 20,099 字符 / 单条 max 530）→ **需重启 DSH 桌面端后复核**；若仍不生效，则回落为「不动内核目录」，原生目录的 20K 固定开销保留。
- **定时提醒轮次不注入**（独立票 #20）：判据只认普通用户消息，提醒投递走 inbox 通道取不到。
- **`~/.dsh/AGENTS.md` 每轮被丢弃**：65,312 B + 仓库 442 B > 65,536 B 预算 → 工作区手册整份不进模型（独立票待开）。
- **hooks 是潜在的第二条注入通道**：`~/.dsh/hooks/hooks.json` 当前不被 DSH 消费；装了 `dsh-hooks-claude-code` / `dsh-hooks-codex` 桥后，`wikiskill_booster.py` 会重新加入注入链路。

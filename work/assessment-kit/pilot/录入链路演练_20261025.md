# 录入链路演练（2026-10-25）

> **性质：这不是真人试测。** 本文件用一份**假造的手抄风格回收登记表**撞录入工具，验证「真人手抄」这件事
> 会不会把工具撞炸、或把脏数据静默放过去。**本文件里的任何数字都不构成信效度证据**（口径见
> `docs/adr/0007-合成试测只验程序不验信效度.md`）：这里的样本是造出来的，α、分布、档位全是生成模型的性质。

## 为什么做这个

票 #26 要收 60–80 份真人作答，回收登记是**手抄**的（作业包 §四的字段，逐份手填）。
上一轮交付的 `ingest_real.py` 只在自己的合成 fixture 上自检过（42 项断言），没被真人手抄风格撞过。
真人手抄的高频写法有四种：**答案写成逗号分隔**、**时刻写成「2026-10-25 09:00」**、**时长写成「5分12秒」**、
**id 抄重复**。这四种里，后两种必须被挡住。

## 假数据怎么造的

一张 6 行的回收登记表（字段与作业包 §四一致，25 列表头由 `ingest_real.py --template` 生成）：

| 行 | 身份 | 造的脏点 |
|---|---|---|
| 1 | 干净行（内部候选人 / 经理） | 答案**逗号分隔**、时刻**中文写法**、批次用时 220–247 秒不等 |
| 2 | 干净行（在职员工 / 专员） | **中途退出**（`midway_exit=有` + 退出时刻 + 现场备注「接电话后离开」） |
| 3 | 脏行 | 只答了 **50 题**（answers 长度 50） |
| 4 | 脏行 | 批次用时写成 **「5分12秒」** |
| 5 | 脏行 | **id 与第 1 行重复** |
| 6 | 脏行 | 答案里混进字母 **x** |

答案本身是随机 0/1（`random.seed(42)`），**不来自题库、不代表任何人的作答**。

## 第一轮：撞脏数据 → 整批阻断

```
python3 pilot/ingest_real.py --csv 回收登记表_手抄风格.csv --out-dir out/
```

结果（退出码 **1**，**输出目录里一个文件都没写**）：

```
校验未通过：发现 4 处硬错误，**没有写出任何输出文件**。
  - CSV 第 4 行（数据第 3 行）字段 answers：分隔后是 50 个值，应为 96 个（作业包 §六：96 个 0/1，0 = 选 a 侧，1 = 选 b 侧）
  - CSV 第 5 行（数据第 4 行）字段 b1：「5分12秒」不是非负整数（毫秒）
  - CSV 第 6 行（数据第 5 行）字段 id：与第 2 行的 id 重复（回收核对与防重复提交用）
  - CSV 第 7 行（数据第 6 行）字段 answers：含非 0/1 的值：x（作业包 §六：96 个 0/1，0 = 选 a 侧，1 = 选 b 侧）
请改 CSV 后重跑；「CSV 第 N 行」是物理行号，「数据第 M 行」是第几份样本（空行与 # 注释行不计入）。
```

**逐条指到物理行号 + 字段名 + 错在哪 + 口径出处**，且明确区分「物理行号」与「第几份样本」。

## 第二轮：施测人改完 → 放行，提醒项照报

改法与真人会做的一样：补齐第 3 份的 96 题、把「5分12秒」改成 **312000** 毫秒、把重复 id 改成新编号、把字母去掉。
再跑 → 退出码 **0**，产出四个文件：

| 产物 | 内容 |
|---|---|
| `real_samples.json` | 顶层只有 `meta` / `respondents`；每份只有 `id` / `group` / `responses` / `times_ms`；`responses` 与 `times_ms` 长度均 96 |
| `excluded_ids.json` | 人工判定要剔除的 id（本次为空） |
| `回收登记表_回收后.csv` | 登记字段原样回带（逐字节） |
| `ingest_report.json` | 逐份样本的校验结论与提醒项 |

**批次折算核对**：`times_ms` 96 个值只有 **10 个台阶**（第 1–9 批各 10 题、第 10 批 6 题，按每批题数折算每题均毫秒），
与作业包 §四/§六 的批次计时法一致。

**提醒项确实报出来了**，且带口径出处，例如：
- 「登记了中途退出「有」：作业包 §二 的有效作答要求「无中途退出」，这份要人工复核是否剔除」
- 「第 N 行 result_json：缺结果 JSON 文件名（作业包 §三：当场收回，作业包 §四：归档用）」
- 「第 N 行 quality_note：缺作答质量备注（作业包 §四：施测人现场观察，例如是否中途接电话、是否明显敷衍）」

提醒项**不阻断**（只有硬错误才整批阻断）——这条是刻意的：缺一个归档字段不该让 60 份数据全废。

## 整链跑通

```
node    pilot/run_pilot.mjs pilot/out/real_samples.json          # 真实计分（同一段 report.js）
cp pilot/out/scored.json pilot/out/real_scored.json
python3 pilot/analyze.py --real ... --scored ... --exclude ...
```

跑通，无异常；`analyze.py` 输出里带「整体档 = 最低维档 规则：通过」。
> **更正（2026-10-25 13:0x · ADR-0010）**：第一项已不给总档 ⇒ 这行输出改为「**短板维 = 四维最低维档 规则：通过**」，`analyze.py` 也不再统计第一项的整体档人数（改为四维各档人数 + 短板维人数）。

> **注意一个易踩点**：`run_pilot.mjs` 固定把计分结果写到 `pilot/out/scored.json`（**不跟随输入文件路径**）。
> 所以真人路径要把输入也放在 `pilot/out/` 下（README 里的命令就是这么写的）；若从别处喂样本，
> 记得从 `pilot/out/scored.json` 拷。

## 工具能力边界（这次演练暴露的）

1. **答案顺序验不了**：工具只验「96 个 0/1」，验不了「是不是按题库顺序作答」。顺序错了**不会报错**，
   只能靠现场纪律（INT-01…24 → SNT-01…24 → TFS-01…24 → JPS-01…24）。
2. **逐题时间只有 10 个台阶**：96 个 `times_ms` 里只有 10 个不同值，批次内部的真实快慢分不出来。
   异常判定阈值拿到真实时长分布后**必须重新标定**（作业包 §九 风险 2）。
3. **乱答识别不在录入环节**：`analyze.py` 的异常盲检（同侧作答 > 90%、相邻同侧 > 80%、96 题全选锚定端等）
   是在**分析**阶段做的，且它的阈值是**临时值**（真人的逐题时间还没采集过）——不要在录入环节把它固化成硬错误。
4. **批次切分口径**：演练沿用工具默认（第 1–9 批各 10 题、第 10 批 6 题）。这条**待维护者确认**（票 #26 的 Q3）。

## 结论

录入链路在**手抄风格**下可用：脏数据被逐条挡下、干净数据一次放行、提醒项不误伤、整链跑通。
但**流程可靠性依赖现场纪律**（答案顺序、批次用时记的是「本批用时」而不是「从开考起的累计」），
这两条工具查不出来——所以《施测动作清单_一份被试_20261025.md》把它们写成了现场动作。

# 施测动作清单（一份被试）

> **打印一份、贴在施测台上，照着做。** 全程不提前算分、不看被试的答案。
> 口径依据：真人试测作业包_20261024.md §三/§四、票 #26 范围第 2/3/4/13 条。
> 配套工具：`pilot/preflight.py`（发卷前预检）、`pilot/ingest_real.py`（收完一份就转一次）。

---

> **口径更新（2026-10-25）**：维护者已定「链接 + 谁填谁作答 + 每人一份报告」（云上版），
> **本清单降级为离线路径的备件**（无网施测、打印件、应急场合）；云版不再需要现场发放与回收登记。

## 0. 发卷前（整批做一次）

- [ ] 跑一遍预检，全绿才发卷：`python3 pilot/preflight.py`
- [ ] 确认**成品**是哪一份（预检会打印文件名 + sha256 前 12 位），把它抄在登记表抬头
- [ ] 打印回收登记表：`pilot/out/回收登记表_模板.csv`（表头 25 列，工具会拒绝示例行）
- [ ] 确认**计时口径**：成品当前是 **B（页面到点自动交卷）**；Q2 未拍板前**两套并存**——
      页面自己会到点交卷，**施测人也按统一时点收卷**；页面先交卷的，以**页面交卷时刻**为准
- [ ] 确认批次切分（第 2 节要用）：第 1–9 批各 10 题（第 1–90 题），第 10 批 6 题（第 91–96 题）

---

## 1. 发卷

- [ ] 把成品单文件给被试（U 盘 / 邮件 / 局域网都行），被试**用自己��设备**打开
- [ ] 念第一句：「全程 **90 分钟**。页面自带倒计时，到点会自动交卷。中途关掉页面再回来，**时间继续走**。」
- [ ] 念第二句：「结果只存在**你自己这台设备**上，不上传服务器。交卷后请**下载结果文件**发给我。」
- [ ] 被试：首页填姓名与身份证 → 告知卡 → 勾「开启限时模式」→「同意并开始测试」
- [ ] **记下开始时刻** → 填登记表的 `start_at`

---

## 2. 作答中（施测人只做两件事）

- [ ] **批次计时**：每答完一批就记一次**这一批花了多久**（毫秒）

  | 批次 | 题号 | 批次 | 题号 | 批次 | 题号 |
  |---|---|---|---|---|---|
  | 1 | 1–10 | 5 | 41–50 | 9 | 81–90 |
  | 2 | 11–20 | 6 | 51–60 | 10 | 91–96（6 题）|
  | 3 | 21–30 | 7 | 61–70 | | |
  | 4 | 31–40 | 8 | 71–80 | | |

  ⚠️ 记的是**本批用时**，不是「从开考起累计到这一批」——两种记法算出来的时长完全不同。

- [ ] **现场观察记一句** → `quality_note`（是否中途接电话、是否明显敷衍、是否提前离场）

---

## 3. 收卷时（当场）

- [ ] 以**页面实际交卷时刻**为准 → 填 `end_at`；再算 `actual_min`（分钟）
- [ ] 确认被试**已下载结果文件**（完成页有「回传给施测人」按钮）→ 收到文件
      > 回传**方式**（发文件 / 直取）与现场话术以「回传引导统一话术」票的裁定为准；备选方案与话术草稿见 `pilot/回传方案草稿_20261025.md`（草案，**未拍板**）。
- [ ] **按测评编号给文件改名**（例如 `EQ-20261025-0001.json`）→ 填 `result_json`
- [ ] 记 `midway_exit`（无 / 有）+ 退出时刻；被试提出复核诉求 → `review_request`（无 / 有）+ 受理日期与诉求

---

## 4. 登记（一行一份，字段与作业包 §四 一致）

| 字段 | 填什么 | 口径 |
|---|---|---|
| `id` | 测评编号（**不要写完整身份证号**） | 回收核对与防重复提交 |
| `group` | 内部候选人 / 在职员工 | 只有这两个值 |
| `level` | 专员 / 经理 / 总监 / 其他 | 岗位层级 |
| `dept` | 部门（在职员工必填） | |
| `id4` | 身份证**后 4 位** | 不记全号（ADR-0004） |
| `start_at` / `end_at` | 开始 / 收卷时刻 | 例：`2026-10-25 09:00` |
| `actual_min` | 实际用时（分钟） | |
| `b1`..`b10` | 每批**本批用时**（毫秒） | 见第 2 节切分 |
| `answers` | 96 个 0/1 | 0 = 选 a 侧、1 = 选 b 侧；顺序 = 题库顺序（INT→SNT→TFS→JPS，各 24 题）|
| `midway_exit` / `exit_at` | 无 / 有 + 退出时刻 | |
| `review_request` | 无 / 有 + 受理日期、诉求 | |
| `result_json` | 结果 JSON 文件名 | 归档用 |
| `quality_note` | 施测人现场观察 | |
| `exclude_reason` | 无 / 人工判定剔除的理由 | 填了才剔除 |

> **答不完怎么办**：每题必选、未答不能跳下一题；到点自动交卷时未答的题**按未作答处理**（不计入得分），
> 结果 JSON 会带「限时到点自动交卷」标记。

---

## 5. 交接（**每收一份就转一次，不要攒到最后**）

```bash
python3 pilot/ingest_real.py --csv <回收登记表.csv> --out-dir pilot/out/
```

- **报错 = 整批不写**：按提示改那一行再跑（它会指到「第几行、第几个字段、错在哪」）
- **提醒项不阻断**：缺归档字段、中途退出、时长矛盾等会进 `ingest_report.json`，人工看一眼
- 攒到一批（10–20 份）后跑整链：

```bash
node    pilot/run_pilot.mjs pilot/out/real_samples.json
cp pilot/out/scored.json pilot/out/real_scored.json
python3 pilot/analyze.py --real pilot/out/real_samples.json \
        --scored pilot/out/real_scored.json --exclude pilot/out/excluded_ids.json
```

## 6. 异常处置

| 情况 | 怎么记 | 后续 |
|---|---|---|
| 中途退出 | `midway_exit=有` + `exit_at` | 作业包 §二：有效作答要求**无中途退出** → 人工确认是否剔除（写 `exclude_reason`）|
| 到点自动交卷 | 正常记（以页面交卷时刻为准） | 票 #26 §13：被截断的份数**不进入信度与分布统计**，要逐份登记（份数、未答题数、落在哪一项）|
| 被测答不完/乱答 | 照实登记 | 由 `analyze.py` 的异常盲检挑出来（**不靠现场判断**）|
| 复核申请 | `review_request=有` + 日期与诉求 | 走测评负责人那条线 |

---

## 7. 明确不做的事

- ❌ 不提前算分、不看被试的答案、不在报告里透露别人的分数
- ❌ 不因**单个候选人**的表现调阈值（校准要等累计 ≥100 份有效作答）
- ❌ 阈值与题库的改动**只在真人证据支持下做**，且要留痕（改了哪题、为什么、复跑结果）
- ❌ 回收表里的身份证**只写后 4 位**；结果文件与登记表**只留本机**

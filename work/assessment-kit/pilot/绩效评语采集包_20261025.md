## 0. 为什么现在就要采集（不能事后补）

绩效评语是票 #26 十三条验收里**唯一依赖第二来源数据**的一条（其余都来自这一次试测本身）。它**不能事后补**，原因有三条，缺一条这次校验就只能空着：

1. **要覆盖同一个绩效周期** —— 评语反映的是某一段时间里的工作表现；事后去找一份「差不多那段时间」的评语，覆盖的是别的周期，与这次作答对不上。
2. **要盲化** —— 评语的书写者必须**不知道测评结果**。如果评语是在看到测评结果之后写的，那它就不是独立来源，一致率会假性升高。
3. **要匿名** —— 评语必须能与人脱钩，否则评语里的姓名、工号会跟着进入分析产物。

**第一场试测一旦开始，评语如果那时还没就位，这条验收就只能空着。**

> **口径出处：**《胜任力映射与绩效评语校验方案_20261025.md》§一（原文：「绩效评语仍然不能事后补（要覆盖同一绩效周期、要盲化、要匿名），所以采集口径要提前定」）。

## 一、采集什么

### 1.1 采集对象与范围

| 项 | 口径 | 说明 |
|---|---|---|
| 对象 | **在职员工组**（本轮参加复测的那一组在职员工） | **外部候选人拿不到绩效评语** —— 所以第 10 条的校验**只覆盖在职员工组**，这条要在票面写清楚 |
| 份数 | **每人一份**；建议先覆盖在职员工组全部 ＿＿ 份（作业包分层要求：至少 2 个部门 + 3 个岗位层级） | 分层是为了让映射校验能按岗位族读 |
| 周期 | **最近一个完整绩效周期（12 个月）** | 覆盖不到 12 个月时的处理见 §八（待定） |
| 每份可用标准 | 每份 **≥ 3 句可标行为句**；不足则**该份不参与** | 「可标行为句」= 明确描述了行为、能对应到某个维度的句子 |

### 1.2 每份要什么字段（不要多要）

| 要 | 字段 | 为什么 |
|---|---|---|
| ✅ | **code** | 被试的**测评编号**。它是唯一的对应键，且**不含姓名与身份证任何位**（格式 EQ-{YYYYMMDD}-{6 位随机码}-{4 位校验码}，沿用告知卡清单 §3.4 的既有规则） |
| ✅ | **评语原文** | 本次校验的唯一输入。**原文照抄，不要润色、不要摘句**（摘句会断掉上下文，也会让「矛盾案例」失去解释力） |
| ✅ | **岗位** | 映射校验要按岗位族读；不同岗位族对同一维度的「好」可能定义不同 |
| ✅ | **层级** | 专员 / 经理 / 总监 / 其他 |
| ✅ | **部门** | 覆盖面的核对用 |
| ✅ | **周期** | 覆盖的是哪个绩效周期（例：2025 年度 / 2026 上半年） |
| ❌ | **绩效等级** | 不用。等级是管理者的结论，不是行为句；带上它会让盲评标注者先入为主，破坏盲化 |
| ❌ | **打分 / KPI / 考核得分** | 同上；且本次校验只吃行为句 |
| ❌ | 身份证号 | 不需要。测评编号足够当对应键 |

> **口径出处：** 对象与周期取自《胜任力映射与绩效评语校验方案_20261025.md》§三第 1–2 条与 §三第 6 条（≥ 20 份可用评语、每份 ≥ 3 句可标行为句）；在职员工组份数与分层取自《真人试测作业包_20261024.md》§二；测评编号格式取自《告知卡要素与数据留存规则清单_20261024.md》§3.4。
> ⚠️ 「不要绩效等级与打分」这一条是本采集包的**建议**（**待定（维护者裁定）**）：理由是盲化与「本次口径只吃行为句」；若维护者坚持要等级，须同时写明它**不进入**一致率与矛盾案例的计算，只作背景。

### 1.3 需要多少份才够启动（启动条件，不是达标线）

- **启动条件**：在职员工组累计 **≥ 20 份可用评语**（每份 ≥ 3 句可标行为句）时，第一轮胜任力校验即可启动。
- **这不是验收线**：第 10 条是**定性印证**，不是信效度统计；产出的是**矛盾案例清单**，不是一个百分比。
- **如果凑不满 20 份**：第 10 条的验收范围怎么写 —— **待定（维护者裁定）**（方案 §七第 3 条）。建议：本轮写「**未执行**」并写清原因（票面要写明「未执行」而不是留空）。

## 二、盲化口径（这一节不能改）

### 2.1 三条硬规矩

1. **姓名 ↔ 测评编号用 code 对应。** 交付给分析方的那份里，**不出现姓名、不出现工号、不出现身份证任何位**；每份评语只带一个 code。
2. **评语正文里的姓名/工号要脱敏。** 评语原文里如果出现了本人或他人的姓名、工号、部门名，**在交付前替换成占位符**（例：「张三」→「员工A」「小王」→「员工B」），占位符在同一份文件里保持一致。**不要删句** —— 删句会改变行为句的比例。
3. **对照表只在 HR 手里。** 「code ↔ 姓名」的对照表**不进分析产物、不进版本库、不进 git**（沿用 docs/adr/0004-身份标识采全不存全且对外只显示后四位.md 的「采全不存全」）。**分析者不得同时看到两者。**

### 2.2 谁拿哪一份

| 角色 | 拿到什么 | 说明 |
|---|---|---|
| **HR（采集方）** | 原始评语 + **对照表（code ↔ 姓名）** | 对照表由 HR 保管，用于去标识与最后核对；**不随交付件一起给分析方** |
| **分析方（测评负责人 / 独立标注员）** | 只有 code、评语原文（已脱敏）、岗位、层级、部门、周期 | **看不到测评结果**，也看不到姓名；这是盲化的另一半 |
| **测评结果** | 只在**对照之后**才与测评分合并 | 合并前不得互相可见 |

### 2.3 留存与删除

- 交付给分析方的评语件**按 HR 既有档案规则留存**，到期删除或匿名化；**不长期存放于群聊与个人微信**。
- **评语原文不进 git**（敏感的个人信息，与测评结果不同层级）。分析产物里只保留**脱敏后的结构化标注**（code + 维度 + 支持哪一端 + 一句必要的引文，且引文需去标识）。
- **待定（维护者裁定）**：本项目**交付给分析方的评语件**的留存期。测评数据本身是「≤ 1 年，到期删除或匿名化」（告知卡清单 §4）；**绩效评语原件**属 HR 既有材料，其留存期按 HR 既有规则 —— 但**因本项目产生的副本**（脱敏件、结构化标注）建议与测评数据同口径（≤ 1 年）。

> **口径出处：**《胜任力映射与绩效评语校验方案_20261025.md》§三第 3–5 条；《告知卡要素与数据留存规则清单_20261024.md》§3.2、§3.4、§4；docs/adr/0004。

## 四、不做什么（采集阶段的红线）

- ❌ **不给评语打标签。** 采集阶段只搬运原文。**标注（按句标维度）属于后面的盲评环节**，由分析方在**看不到测评结果**的前提下按方案 §二的规则做，且是**逐句人工标**（按句切开，一句可能标到多个维度；只标明确描述行为的句子，不标性格评价句）。
- ❌ **不做机器评分。** 不跑任何自动打分、情绪分析、关键词打分、LLM 打分。判据只有一句：**机器不代劳判断**（机器只做分歧率、命中率这类可机械计量的判定）。
- ❌ **不外传。** 评语原文与脱敏件都不出 HR 与分析方这条线；不进 git、不进群聊、不进个人设备。
- ❌ **不作为录用依据。** 绩效评语是 HR 既有的考核材料，与测评结果一样**只作追问线索**；测评在录用决策中的位置是「**不作评分项**，只作追问线索」（裁定表 §5）。**不得因为评语进了这次校验，就把评语或测评结果变成录用结论。**
- ❌ **不进对外材料。** 评语内容、矛盾案例原文、个人分数与档位人数一律不出现在对外书面反馈里。

> **口径出处（合规）**：《告知卡要素与数据留存规则清单_20261024.md》§2.4 红线清单（不得出现「决定录用」「淘汰」「唯一依据」等表述）、§3（身份标识：采全不存全、一律只显示后 4 位）、§4（留存 ≤ 1 年、到期删除或匿名化、不长期存放于群聊与个人微信）；《统一五级裁定表_20261024.md》§3（对外只报 4 个合并维度 + 总档 + 辅助参考声明）、§5（测评不作评分项、只作追问线索、留痕要求）。

## 五、采集之后怎么用（**只写框架，不写阈值**）

> 口径依据：《胜任力映射与绩效评语校验方案_20261025.md》§二、§四、§六。**阈值待维护者裁定**，本节不预设。

### 5.1 做法：盲评对照

1. 在**不知道测评结果**的前提下，由评语提供方（或一名**独立于设计者**的标注员）先给每条评语标注「支持该维的**哪一端**」。
2. 标注规则（照方案 §二）：把评语**按句**切开；一句可能标到多个维度；**只标明确描述行为**的句子，**不标性格评价句**（「比较强势」「有点固执」没有行为落点，不标）；每句只能标一次主维度，必要时标次维度。
3. **然后**才与测评分对照，分三类：

| 类别 | 判定 | 处理 |
|---|---|---|
| **一致** | 评语支持的行为 = 该维的高分端 | 计入一致率 |
| **矛盾** | 评语支持的行为 = 该维的低分端 | **逐条人工读**（最有信息量的一条） |
| **无法判断** | 评语没涉及该维 | **不计入分母** |

4. 产出两张表：**一致率表**（每维 一致数 /(一致数+矛盾数)）＋ **矛盾案例表**（每条一句人话：矛盾在哪、可能是岗位奖励另一端 / 评语笼统 / 题目与岗位错位；结论分三类：**题库要改 / 岗位本来就要另一端（该维对这个岗位族不适用）/ 评语不可用**）。
5. **边界**：本校验**不进**信度、分布、极端题、社赞偏差的统计；**不产生分档**；**不因**本校验而提前或推迟校准（方案 §五）。它的作用只有一个：回答「第一项测的东西是不是 HR 真的在用的那套标准」。

### 5.2 不设一刀切阈值

**建议的用法**：**逐条读矛盾案例**，把矛盾归到「题库要改 / 岗位不适用 / 评语不可用」三类，**只有「题库要改」那一类才动题目**（且要留痕、要复跑）。

**不建议**用「一致率 ≥ 某值就通过 / 整维否掉」这种一刀切判据 —— 方案里那条「一致率 ≥ 60% 视为该维映射成立」是**建议**，**阈值待维护者拍板**（方案 §四、§七第 1 条）。理由：低一致更常见的解释是评语笼统、维度在真实岗位里区分度低（尤其 SNT 与 TFS），或岗位确实奖励另一端 —— 那属于「题目与岗位错位」或「该维对这个岗位族不适用」，**不是「人测错了」**。

### 5.3 两条读法陷阱（写在这里，是为了让读报告的人不读反）

- **一致率高 ≠ 测评准。** 绩效评语本身受绩效动机影响（写得让人满意也是绩效流程的一部分）；两者一致可能来自「评语在迎合测评之外的印象」。**一致率只是收敛性证据，不是效度证据**，也不写进信效度结论。
- **一致率低 ≠ 测评不准。** 低一致更常见的解释是：评语笼统、维度在真实岗位里区分度低（尤其 SNT 与 TFS），或**岗位确实奖励另一端**（那是题目与岗位错位）。
- ⇒ **一致率不是信度指标**（方案 §四）。

> **口径出处：**《胜任力映射与绩效评语校验方案_20261025.md》§四、§五、§六、§七。

## 六、多久要 / 时间表（两条轨道并行）

### 6.1 两条轨道，不要互相等

| 轨道 | 目标 | 触发条件 | 依赖 |
|---|---|---|---|
| **轨道 A：复测作答样本** | 第一份**描述式诊断报告** | 累计有效作答 **n ≥ 60**（Q3 第一道关） | 发放与施测进度 |
| **轨道 B：绩效评语样本** | 第一轮**胜任力校验**（盲评对照） | 在职员工组累计 **≥ 20 份可用评语**（每份 ≥ 3 句可标行为句） | 绩效评语的产出周期 + HR 脱敏工时 |

- **复盘（复测诊断）与评语采集可以并行**：轨道 A 到 n ≥ 60 就能出第一份描述式诊断，**不必等评语收齐**；轨道 B 的校验也不必等第一份诊断。复测报告里第 10 条那一节在评语未收齐时写「**未执行**」并写清原因（见复测模板 §七.2）。
- **两个 n 不要混**：n ≥ 60 是**作答样本**的门槛（Q3）；≥ 20 份可用评语是**评语样本**的启动条件（方案 §三第 6 条）。两者不是同一个数，也不是同一个样本。

### 6.2 「第一批数据到 n ≥ 60 大约需要多久」的提醒

- **这件事不能靠排期表保证，只能靠一个可观测的触发条件**：轨道 A 的第一份描述式诊断在**累计有效作答 n ≥ 60** 时出（Q3）；轨道 B 的第一轮校验在**累计 ≥ 20 份可用评语**时启动。
- **本采集包不编日历天数**：评语到齐的时间取决于两件仓内没有依据的事 —— ① 本集团的**绩效评语产出周期**长度（季度 / 半年 / 年度）；② HR 做编号、脱敏、归档的**人工工时**。
  ⇒ **待定（维护者裁定）**：① 本集团绩效周期长度与第一批评语的交付日期；② 脱敏由谁做、投入多少人日。
- **保守的结论**：从现在开始采集，到第一批可用评语到齐，**至少要跨过一个完整的绩效评语产出周期**。**正因为有周期，采集才必须现在就开始** —— 事后补是补不上的（§0）。
- **可以先做完、不用等周期的那部分**：**编号与脱敏管道**（code 规则、占位符规则、交付表头、交接记录）**先建好**；等评语一到就能直接进池子，不必再走一遍流程设计。

## 七、最小可行清单（给 HR 照着做，逐条勾）

**A. 采之前（一次做完）**

- [ ] 确认**采集对象**：本轮在职员工组名单（外部候选人不采；这一条要在票面写清楚）
- [ ] 确认**绩效周期**：本轮要覆盖哪个完整周期（12 个月）；覆盖不到时按 §八 处理
- [ ] 拿到被试的**测评编号 code 列表**（code 不含姓名与身份证任何位）
- [ ] 建立**脱敏规则**：姓名/工号/部门名 → 占位符（员工A、员工B…），同一份文件内一致；**不删句**
- [ ] 准备好**交付表头**：code / 评语原文 / 岗位 / 层级 / 部门 / 周期（一个 xlsx 或 csv）
- [ ] 准备好**对照表**（code ↔ 姓名）的存放位置：**只在 HR 手里，不随交付件外发**
- [ ] 确认**不采集**：绩效等级、打分/KPI、身份证号

**B. 采集（每份一份）**

- [ ] 每人取**一份**绩效评语原文（最近一个完整绩效周期），**照抄不润色**
- [ ] 核对这份评语**是否 ≥ 3 句可标行为句**；不足的**不参与**，但**仍要登记**（说明原因）
- [ ] 记下：code、岗位、层级、部门、周期
- [ ] **脱敏**：正文里的姓名/工号换成占位符
- [ ] **不要**在这一步做任何标注、打标签、打分

**C. 给回来**

- [ ] 汇总成**一个 xlsx 或 csv**，六列齐全
- [ ] 自查一遍：**文件里没有姓名、没有工号、没有身份证任何位**（用检索确认，不要凭印象）
- [ ] 自查一遍：**没有绩效等级、没有打分列**
- [ ] 附一行**交接记录**：交付日期、份数、交付人、接收人
- [ ] 交给**测评负责人**；存**受控目录**，**不进版本库、不进 git、不进群聊**
- [ ] 告知对方：**这批材料在盲评对照完成前不得与测评结果合并**；对方也**不得**向第三方转发

**D. 收到之后（一句提醒，不是给 HR 的活）**

- [ ] 分析方在**看不到测评结果**的前提下先做盲评标注（规则见 §五.1）
- [ ] 对照之后产出一致率表 + **矛盾案例表**；**只有「题库要改」那一类才动题目**（动题留痕、复跑）
- [ ] 结果回填复测报告模板的 **§七「胜任力映射与绩效评语校验」**；**评语未收齐时该节写「未执行」并写清原因**

## 2. 哪些能算出来，哪些只能手写

| 字段 | 能不能自动再生 | 说明 |
|---|---|---|
| 三个模块的百分比（79.2% / 80.4% / 95.5% …） | ✅ 能 | 走 `src/report_v2_profile.py` 的 `three_band()`，与单份报告同口径 |
| 每个维度的百分比（92% / 58% / 75% …） | ✅ 能 | `dim_band3()`；取整用「四舍五入 .5 进位」（见下） |
| 维度档位（突出 / 常规 / 偏弱） | ✅ 能 | `band3()`：≥85 突出 / 70–85 常规 / <70 偏弱 |
| 类型归类（ESTJ 推进型 / ENTJ 统筹型） | ✅ 能 | `type_profile()`：四维得分按「严格过半归极 a」拼四字母 |
| 形象类比（工蜂 / 鹰） | ✅ 能 | `animal_profile()`：E/S/J 三轴取动物 |
| 姓名/性别/年龄/学校/专业/职级编码/部门/职位 | ✅ 能 | 来自结果 JSON 的 `profile` 字段 |
| **维度显示名**（归纳推理 / 数量推理 / 约束分析 …） | ❌ 手写 | 单份报告里是全称（归纳推理与模式识别 / 数量推理与数据素养 …），产物里是手写的简称 |
| **维度小注**（推动 / 等待配合、压力下是否稳住 …） | ❌ 手写 | 20 条，仓内任何文件里都没有 |
| **长图的逐维评语**（顶尖水平，主动推动能力强 …） | ❌ 手写 | 3 人 × 20 维 = 60 条，仓内无出处 |
| **整体评价 / 一句话总结 / 测评结论** | ❌ 手写 | 三人各 3 段，仓内无出处 |
| 职级名称（专业三级 / 专业五级） | ❌ 手写 | 来自 HR 库「职级」字段（与结果 JSON 的职级编码 O4-2 是两个字段） |
| 机构简称（安吉半亩田 / 云上余村 / 云上度假村） | ❌ 手写 | 结果 JSON 里是全称（安吉半亩田农业科技 / 山川松鼠部落酒店 …） |
| 学历层次（一本 / 本科 / 硕士） | ⚠️ 半手写 | 结果 JSON 只给「专业（学历）」（本科），「一本」是 HR 另一个字段 |
| 版式与配色（CSS、缩进、行尾空格） | ✅ 能 | 版式常量直接抄自已提交产物，逐字节保真 |

**手写部分一律集中在 `src/comparison_spec.json`**：脚本只装配、不改写文字；
要改判读文字就改 spec 一处，产物跟着变。

### 百分比取整口径
产物里 `15/24` 显示 **63%**、`9/24` 显示 **38%**、`21/24` 显示 **88%** —— 都是 .5 进位，
与 Python 内置 `round()` 的银行家舍入（62.5 → 62）不同。脚本用
`Fraction` + `floor(f + 1/2)` 做整数运算，无浮点误差。

## 3. 脚本与用法

| 文件 | 作用 |
|---|---|
| `src/comparison_spec.json` | 输入：分数（与单份报告同源）+ 手工判读文字 + 版面所需的 HR 字段 + `no_source` 清单（哪些值没有机器来源） |
| `src/build_comparison_artifacts.py` | 生成器：重建三份 HTML（可选 `--png` 一并截图） |
| `src/verify_report_artifacts.py` | 门禁：真源核对 + 三方比对（工作区 / git HEAD），exit 0 = 一致 |

```bash
cd work/assessment-kit

# 重建（写进临时目录，不碰 reports/）
python3 src/build_comparison_artifacts.py --outdir /tmp/rebuild

# 重建 + 与 pilot/out 的原始结果 JSON 核对（生成器自检；找不到结果 JSON 会「跳过」并正常退出）
python3 src/build_comparison_artifacts.py --outdir /tmp/rebuild --cross-check

# 门禁（默认内容判据）
python3 src/verify_report_artifacts.py
python3 src/verify_report_artifacts.py --mode both --png   # 字节判据 + 截图
```

- 生成器**不覆盖**已存在且内容不同的目标文件（要覆盖得显式 `--overwrite`），
  避免手滑冲掉定稿。
- 门禁**只读** `reports/` 与 git HEAD：重建结果一律写进临时目录。
- 门禁与生成器的分工（2026-10-26 加固）：**真源核对由门禁自己做**，结果 JSON 缺失即判红
  （exit 2），不再靠 `--cross-check`；生成器那边的「跳过不算失败」保留 —— 它是生成器，不是门。

## 4. 一致性判据与实测

**三条腿都要绿**（2026-10-26 加固）：
① **真源核对** spec ↔ `pilot/out/结果JSON_*.json`（门禁自己做；结果 JSON 缺失即红，exit 2）；
② **工作区一致** 重建结果 ↔ `reports/` 下当前文件；
③ **已提交一致** 重建结果 ↔ `git HEAD:` 同一路径（仓根下 `git show` 取字节）。
② 和 ③ 分开，是为了抓住「产物被人手改了但没提交」——只比 ② 的话，
把产物改了、再把 spec 改成能复刻它，门禁照样绿。

**判据（`--mode content`，默认）**：把两边 HTML 各归一化成三份可比的东西再比 ——
① **文本序列**（去标签/样式/脚本、实体反转义、空白折叠后按词元比）；
② **版面骨架**（只留标签名 + 排序后的属性，含 `class` 与**内联** `style` 里的配色；
文本节点只留「这里有段文字」的存在标记）；
③ **样式块**（`<style>` 块单独抽出、空白折叠后逐块比）——
以前 `<style>` 被整块剥掉，改个背景色门禁也看不出来，与「能抓配色漂移」的说法不符；
现在样式块是内容判据的一部分，缩进噪声仍按折叠后比，不回到字节判据。

**为什么不用纯字节做门禁**：定稿的实质是「分数、档位、判读文字、版面结构没变」，
不是「编辑器没多敲一个空格」。字节判据会把换行/缩进/行尾空格也算成不一致，
久而久之没人看红灯。字节一致（sha256）作为**更强信号单独报告**。

**实测（2026-10-26 20:2x，加固后，对当前仓库状态）**：

```
· 核心人才三联测试_汇总封面_20261026.html —— A 工作区：一致 / B 已提交：一致
· 三人核心人才三联测试_对比总表_20261026.html —— A 工作区：一致 / B 已提交：一致
· 三人核心人才三联测试_苹果风长图_20261026.html —— A 工作区：一致 / B 已提交：不一致
    文本序列：replace  - 职级 / - 职位  →  + 职级·薪级 / + 机构
    样式块：不同（第 2085 个字符起不同：.conclusion 规则是 HEAD 版没有的）
结论：不一致（exit 1）
```

> 长图那份的工作区版本（20:03 手改，HTML + PNG 都未提交）与 HEAD 不一致，
> 所以门禁报红 —— 这是**应该**的：产物与 spec 一致 ≠ 产物与已提交产物一致。
> 要变绿只有一条路：把长图的改动提交上去，或撤回工作区改动回到 HEAD 版本。

反向自测（构造漂移，确认门禁会亮红灯）：

| 注入的漂移 | 结果 |
|---|---|
| 改一个百分比（92% → 91%） | ❌ 文本序列报差异 |
| 只改缩进/换行 | ✅ 内容判据通过 / ❌ 字节判据 |
| 改一个内联档位配色 | ❌ 版面骨架报差异 |
| 改 `<style>` 里的背景色 | ❌ **样式块报差异**（加固前是假绿） |
| 手抄错 spec 里的分数 | ❌ 真源核对报差异（exit 1） |
| 结果 JSON 缺失（新克隆/CI） | ❌ exit 2：「缺少 pilot/out/结果JSON_*.json，无法核对 spec 真源」 |
| 改 spec 与产物（「一致但错」） | ❌ 对 HEAD 那条腿红 |

## 5. 待维护者拍板 / 需要收口时统一的问题

1. **职级两个口径**：汇总封面写「专业三级 / 专业五级」（HR 职级名称），
   长图写「O4-2 / O4-4 / O3-2」（职级编码）。同一批人、两份产物、两个口径。
2. **学历两个口径**：汇总封面写「本科 / 硕士」（结果 JSON 的 `专业（学历）`），
   长图写「一本 / 硕士」（HR 学历层次）。同一个人的学历在两份产物里写法不同。
3. **类目名**：对比总表的分组标题仍写「第一项 / 第二项 / 第三项」，
   与票 #50 定的对外称谓（人格特质 / 情景处理 / 逻辑分析能力）不一致。
4. **长图评语首词与档位不同源**：60% 在对比总表里是「偏弱」，长图评语却写「常规…」；
   100% 写「满分」、92% 在崔婵处写「顶尖水平」而杨绍会处写「顶尖」—— 首词是手写词，
   不是档位。改档位时这些词不会跟着动。
5. **三份 PNG 是 Chrome 截图**：字节取决于本机 Chrome 版本（换机器/升级 Chrome 可能字节变但图一样）。
   当前三张都能逐字节复现（截图参数：汇总封面 1080×900@1x、对比总表 1180×3200@1x、
   苹果风长图 2160×4440 即 1080×2220@2x）。

## 6. 边界

- 结果 JSON（`pilot/out/结果JSON_*.json`）**不在仓内**（该目录被 gitignore）。
  所以 spec 是「转录」：生成器的 `--cross-check` 用本机结果 JSON 反查转录有没有抄错，
  找不到时**跳过（不算失败）** —— 它是生成器，不是门。
  **门禁**（`src/verify_report_artifacts.py`）自己做这份核对，**结果 JSON 缺失即判红**
  （exit 2，提示「缺少 pilot/out/结果JSON_*.json，无法核对 spec 真源」）：
  拿不到真源就不许说「一致」。跑门禁前请先按 `pilot/` 流程生成结果 JSON。
- spec 里的**无来源手抄值**（判读文字、`edu_tier`、`org`、`hr_level` 等）已逐条登记在
  spec 的 `no_source` 清单里（为什么没有机器来源 / 人工依据是什么 / 风险）；
  门禁会自检这份清单（路径解析不到、钉住的值漂移、必需项漏了 ⇒ 判红）。
- 三份产物的**判读文字无法自动再生**：本轮做的是把「数字与版面」交给脚本、
  把「文字」显式收进 spec 并可断言，不是把文字生成出来。

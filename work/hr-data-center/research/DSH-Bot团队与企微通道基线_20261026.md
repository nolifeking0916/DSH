## 1. Bot（create_bot）与 Team（spawn_teammate / team_task_*）

### 1.1 ds-bot 的 create_bot（A 体系）

- 工具定义 `~/.dsh/profiles/desktop/node_modules/ds-bot/src/host/tools.js:296-329`。参数仅 7 个：`name`、`role`（2–4 字标签）、`instructions`（必填）、`brief`、`model`、`effort`、`work_dir`、`avatar`。
- **只有 Main Bot 能建**：`tools.js:312` —— `if (!rt.isMain(rt.selfOf(exec.agent?.id))) return 'Only the Main Bot can create Bots. Ask the Main Bot instead.'`
- **默认继承创建者的模型**：`tools.js:318-322`（不指定 model 取创建者 model）；`roster.js:140-148` 解析 model/effort，无模型则不许设 effort。
- **每个 Bot = 一个独立 DSH Session**：`roster.js:149` `createSession(cleanName,{dir})`；`roster.js:79-91` 用 `ctx.sessionController.create({cwd|workspaceId, agentPreset:'standard'})`。
- 名字规则：`src/shared/mentions.js:26-33`（非空、不含 `@`/反引号/换行、不能是代词、同名拒绝 `roster.js:136`）。
- Main Bot 概念：`src/host/store.js:343` `isMain = id => state.mainBotIds.includes(id)`；可有多个 Main Bot。

### 1.2 ds-bot 团队怎么协作（消息 + 群聊，**没有共享任务板**）

- `message_bot`（`tools.js:141-267`）：Bot→Bot 单播。`reply_to: me|user`（user＝目标 Bot 在自己聊天里直接回用户，发起方收不到回执）；`when: now|queue`（now＝插入对方下一步，queue＝排到当前工作之后）；`request_id` 幂等。
- **群里 `message_bot` 只到群成员**：`tools.js:122-128, 200-205`（"work for a group stays in it"）。
- `stop_bot`（`tools.js:269-294`）：Main Bot only，取消对方正在跑的 turn。
- **无持久任务板**：跨 Bot 的「谁做哪一步、依赖谁」只能靠群聊 + 消息约定。

### 1.3 原生 Team（spawn_teammate / team_task_*）

- 工具定义 `asar:dsh/node_modules/@deepseek-ai/dsh-experimental-tool-agent-team/lib/index.js`：`spawn_teammate` L251、`send_message` L292、`list_agents` L320、`interrupt_agent` L351、`team_task_create` L365、`team_task_list` L400、`team_task_get` L444、`team_task_update` L457。
- **按 Agent scope 注入**：`lib/index.js:534-553` 只在 `ctx.agentTeams.tryMembership(agent) !== undefined` 的 Agent 里注册；`lib/index.js:228` 取该 Agent 私有 ctx。
- **成员判定**：`asar:dsh/node_modules/@deepseek-ai/dsh-experimental-agent-team/lib/index.js:869-899` `tryMembership` —— root session（无 parentSession 且非普通 subagent）= **lead**；spawn 出来的成员 = **teammate**；普通 subagent 返回 undefined（拿不到 Team 工具）。
- **上限**：`asar:dsh/node_modules/@deepseek-ai/dsh-experimental-agent-team-profile/cordis.patch.yml` 里 `maxMembers: 8`（默认 16）、`maxTasks: 256`、`maxMessageBytes: 65536`。
- README 限制：只支持「一个共享工作目录内的协作」，不支持分离工作目录、跨进程协调、自动释放任务 owner；需要 durable session storage。
- **`write_scopes` 只是建议不是锁**：`agent-team/lib/index.js:371`（"write scopes overlap … warnings.add(...)"）；`tool-agent-team/lib/index.js:29` teamPolicy 原文 "Write-scope overlap is advisory, not a lock"。路径必须 workspace 相对（`agent-team/lib/index.js:810`）。
- 阻塞依赖：任务有 `blockers`，依赖未完成不可 claim；每次变更 compare-and-set，过期 revision 的更新被拒。
- 实测：本会话（delegated subagent scope）**没有** `spawn_teammate`/`team_task_*`（`cordis_inspect_query` host/Tool/listTools grep 计数 = 0），有 legacy `subagent`/`subagent_fork`/`list_agents`/`send_message`/`interrupt_agent`。`Config.listConfigs` 显示 `include:tool-agent-team` = `schema`（活），`tool-subagent*` = `inactive`。

## 2. 群聊（create_group / post_to_group / group_relay / message_bot）

### 2.1 建群与改群

- `create_group`（`tools.js:448-475`）：**Main Bot only**（L462）；`members` 必填（Bot 名字数组），自己自动加入；可设 `name` `notice`（共享守则，每个成员发言前读）`admin`（默认自己）`mode`。
- `update_group`（`tools.js:477-536`）：Main Bot 可改任意群；群 admin 只能改自己那个群；可 `add_members`/`remove_members`/`admin`（传 `"none"` 清空 admin，仅 Main Bot）/`mode`/`work_dir`（**只有 Main Bot 能设群工作目录**，L498）。
- `delete_group`（`tools.js:538-553`）：Main Bot only，群正在跑轮次时拒绝（L549）。
- **群成员上限 12 个 Bot**：`src/host/constants.js:56` `ROOM_MAX_MEMBERS = 12`，检查在 `roster.js:369`。

### 2.2 mode / admin 语义

- `mode` 只有 `everyone` / `admin`（`constants.js:53` `ROOM_MODES`）。**新群默认 `admin`**（`constants.js:49-52`：每个多余发言者都要重读自己的上下文，所以默认只到 admin）。
- `admin` 模式：普通消息先到 admin，admin 用 `@Name` 点名其他人；`everyone` 模式全员依次回答、admin 先。
- 选发言者逻辑：`src/host/groups.js` `openingSpeakers()`（约 L745-760）——被 `@` 的优先；否则 admin 模式只有 admin，everyone 模式 admin + 其余成员。

### 2.3 发言与路由

- 群里能发言的：用户 + 群成员 Bot。群还有一个**中继 Session（relay）**，不是参与者，只调用 `group_relay`（`prompt.js:57-63`：每条用户消息必须恰好调一次 `group_relay` 然后空回复；`groups.js:559` 工具定义）。
- 路由：用户消息 → 中继 Session → `group_relay` → 按 `openingSpeakers` 选本轮发言者 → 每个成员用**自己在这个群里的隐藏 Session** 发言（`store.js:346-352` 注释："Each member has its own hidden Session per group, so a group never reads a Bot's private chat"；Session 在成员首次在群里发言时创建，`groups.js:204`）。
- 成员回复回到群里：是（`post_to_group` 返回值原文 `tools.js:605`）；`report_back=true` 会**额外**把成员回复作为新消息回传给发帖者（`tools.js:561, 586-590`）。
- `post_to_group` 权限：Main Bot 可发任意群；普通成员只能发自己所在群；**普通成员的帖子只点名它 `@` 的人**，没点名就 "Nobody answers it"（`tools.js:571-581, 595`）；Main Bot 或群 admin 的帖子开启一整轮讨论（`tools.js:557`）。
- 群里 `message_bot` = 等价于写 `@Name`（`tools.js:130-134`），不会把工作送到群外 Bot。
- `read_group_chat`（`groups.js:715-745`）：Main Bot 可读任意群，其他人只能读自己在的群；只给最近若干条，长行截断并提示用 `seq` 读全文。

## 3. 记忆层（remember / recall 的 scope）

存储位置 `~/.dsh/bot/memory/` —— `bots/<botId>/`、`groups/<roomId>/`、`team/`（`memory.js:462-476` `dirOf/scopeKey`）。每个 scope 下 `MEMORY.md` + 若干 topic 文件（`[[topic]]`）。上限：单条 300 字符、MEMORY.md 4000、topic 16000、每 scope 40 topic（`memory.js:714-731`）。

四个 scope（`memory.js:691-702` `namedScope`，接受 `own|me|self|自己|我` / `group|群|本群|群聊` / `team|团队|共享` / 某个 Bot 的名字）：

| scope | 谁读 | 谁写 |
|---|---|---|
| `own`（Bot 私有） | 该 Bot 全部会话 | 该 Bot 自己；别的 Bot 只有 Main Bot 能改（`writeDenied` L706） |
| `group`（群记忆） | **仅该群成员，且仅在群会话里**（`memory.js:1156-1160`） | 仅该群成员，且仅在群会话里 |
| `team`（团队共享） | 所有 Bot（默认就在 recall 范围） | **仅 Main Bot 和任意群 admin**（`writesTeam` L687、`writeDenied` L704） |
| 某个 Bot 的名字 | 仅 Main Bot 能读别人的（`readScopes` L1161） | 同 own |

默认行为：`remember` 在自己聊天默认写 own，在群聊默认写 group（除非显式 `scope:"own"`，`memory.js:331`）；`recall` 不传 scope 时搜 own + team（群聊里 own + group + team）；`forget` 同 scope 规则。**记忆是数据不是指令**（`memory.js:310` memoryRules），像密钥/口令/ID 的条目会被拒（`memory.js:712-718`）。每轮后有 memory review 自动整理，群记忆由 **admin 的模型**维护（`keeperOf` L481）。**只有团队里的 Bot 能用**（`recall` L1178："Only Bots on the team keep a memory."）——普通 root session 会被拒。

## 4. 能力挂载（save_capability / attach_capability）

- `save_capability`（`tools.js:799-828`）在 `state.capabilities.items` 登记，kind ∈ {mcp, skill, pack}；名称 `^[a-z][a-z0-9]*(?:-[a-z0-9]+)*$`、≤32 字符、`github` 保留（`capabilities.js:10-16`）；pack 只能包含已存的 mcp/skill（`capabilities.js:125-130`）；改动**从下一条消息起生效**。
- `attach_capability`（`tools.js:844-871`）：挂给自己，或你是 Main Bot 时挂给别人（`capabilities.js:162`）。谁能改：`allowedToEdit = rt.isMain(botId) || item.createdBy === botId`；别的 Bot 正在用时只有 Main Bot 能改（`capabilities.js:76-86`）。
- 实现关键：`capabilities.js:275-320` `mountOne` → `agent.ctx.plugin(plugin, config)`，把 MCP client / skill **挂进该 Bot 自己的 Agent context**——这是**真正能做到「不同 Bot 不同工具集」的唯一入口**。
- **stdio 型 MCP 需用户批准**（新建/改动时 `approved=false`，状态 `needs-approval`；`capabilities.js:113`），streamable-http 型直接可用（L120）。
- **Bot 能否直接用 `mcp__hrq-pg__query_sql` / `mcp__cloudbase__*`：能，走另一条路**——这三个 MCP 全局注册在 `~/.dsh/cordis.patch.yml`（`mcp-hrq-pg` / `mcp-cloudbase` / `mcp-memos-api`），对所有 profile、所有 Session、**每个 Bot** 生效，**不需要 attach**。即：**HR 取数不需要走 capability**；capability 的价值是给某个 Bot 额外挂一套 MCP/技能。

## 8. 对「建 HR 数据中心专家团队（可群聊）」的可执行结论

**能直接用**
1. **Chief + 一批 HR 专家 Bot**：用户在 **Chief 的聊天**里下指令 → Chief 调 `create_bot`（每 Bot 独立 model/effort/instructions/work_dir）。Bot 数量无上限，群成员 ≤12。
2. **HR 群聊**：`create_group`（Chief 为 Main Bot，默认 admin）→ 成员 Bot 用各自隐藏 Session 在群里发言，用户普通消息先进 admin，Chief 用 `@Name` 派活。
3. **数据出口已通**：HR 取数靠**全局 MCP**（`mcp__hrq-pg__query_sql`、`mcp__cloudbase__*`），**不需要 attach capability**；`save_capability`/`attach_capability` 只在给某 Bot 额外挂 MCP/技能时才用（stdio MCP 还要用户在设置里批准一次）。
4. **三层记忆对应 HR 口径分层**：Bot 私有记忆（个人偏好）、群记忆（本次专项临时共识）、**团队记忆（全局口径：在职定义、剔除清单、机构简称 —— 只有 Main Bot 与群 admin 能写）**。
5. **两层协作可叠加**：ds-bot 的「Bot 团队 + 群聊」= 长期角色；原生 Agent Team 的 `spawn_teammate` + `team_task_create`（带 blockers 与 write_scopes）= **单次任务内并行分工**。write_scopes 只是建议不是锁，须自己协调写冲突。
6. **专家库可复用**：agency-agents 的 HR 专家（绩效、招聘）可 `summon_expert`，但要先在 profile 里 enable。
7. **模型可按角色分**：取数型用便宜模型、分析型用强模型（当前默认 `mini/MiniMax-M3.1-Flash`，reasoningEffort=high，见 `~/.dsh/profiles/desktop/cordis.patch.yml` 的 `agent-default-model`）。
